I WHAT IS IT

What It Is

Existing TFT tools only look up the comp tier list — they just tell you "this comp is strong." This project fills both ends: while you play, it reminds you which augment to pick · whether to level up · who to give the item to; once you finish, it auto-generates a review report with quantified counterfactuals.

At its core: one perception layer · two product paths. The OBS virtual camera feeds the real-time path · mp4 recordings feed the post-match path · both flow through a shared frame_monitor / OCR / VLM / S17 RAG · produce a consistent WorldState · then fork into real-time advice or full-match review.

II DUAL ENTRY

Two Product Paths

One in the moment · one after the fact. They map to two real needs: "I want reminders while I play" and "I want to review after I finish."

III ARCHITECTURE

Technical Architecture

Both product paths share one perception layer. Pick one of two data sources · unified perception layer · analysis layer forks on demand. Design goal: let specialized models do specialized work — each layer fails independently without contaminating the others.

Layer · Code What It Does Why Not Hand It All To The VLM
OCR layer
ocr_client.py · PaddleOCR		 Reads the numbers for HP · gold · level · win streak In testing, Qwen2.5-VL often misreads HP by 1-2 · fatal for data analysis. OCR is a stable 99%+ · and its failure modes are predictable.
CV layer
arrow_finder.py · OpenCV		 Finds item icons · unit positions · the center of highlighted UI elements Color thresholding + shape matching in 30 lines is enough · an order of magnitude faster than the VLM · and it won't "hallucinate" icons that aren't there.
VLM layer
vlm_client.py · Qwen3-VL-8B/4B-FP8		 Trait semantics · opponent comp classification · tutorial guidance text Keep the VLM for the semantic tasks it's genuinely good at · don't make it read numbers it handles poorly. When VRAM is tight, drop to 4B-FP8.
Analysis layer
llm_analyzer.py · decision_llm.py		 Real-time 6 decision types / post-match full synthesis · quantified counterfactuals Needs S17 patch-knowledge RAG · defaults to local vLLM at zero API cost. A new season only swaps the RAG · no model retraining.
Why a Hybrid, Not a Bet on a Single Large Model

In testing, Qwen2.5-VL-7B frequently misreads HP by 1-2. Switching to Qwen3-VL-8B-FP8 is accurate enough · but 16 GB of VRAM can't fit it alongside the MuMu emulator · so dropping to Qwen3-VL-4B-FP8 is the VRAM-sensitive option. In the end — specialized models do specialized work · each layer fails independently — far more robust than betting on a single large VLM. This architectural judgment is itself worth putting on a resume.

V COMPLIANCE

Why Tencent Can't Detect It

This is not "boosting with a new skin." From the data source to the execution surface, it deliberately stays away from the game process — Tencent's anti-cheat sees nothing abnormal · and you can put it on a resume with a clear conscience.

Screen Only
read-only capture
The data source is the OBS virtual camera · essentially just another video stream. No hooking into the game process · no reading game memory · no sending any input commands. Every action is still performed by the player themselves.
Local Inference
local vLLM first
Perception / analysis / decision share a single local vLLM instance · with zero API cost · zero network dependency by default. To go cloud, just write a CloudLLMAnalyzer drop-in · the interface stays the same.
No Android
no adb / no hook
The data-source stage once used ADB screen capture — that whole layer has now been replaced with the OBS virtual camera. No connection to the Android side · no scrcpy · no accessibility · the emulator thinks it is merely being recorded.
C O M P L I A N C E S T A C K
  • OBS Virtual Camera captures only, never controls · same category as streaming software
  • The Python side only takes the video stream · never touches the MuMu process
  • PyQt overlay is click-through · doesn't intercept clicks
  • No ADB / scrcpy / Accessibility / Frida
  • No input injection · the final action is still the player tapping the screen
  • No automation · no auto-clicking · no pathing
VI HOW TO RUN

How To Run It

Shortest path — no OBS · no Windows · run the full chain inside WSL · get an HTML review in under 50 seconds. Want the real-time coach? Then go the Windows four-terminal route.

P O S T - M A T C H R E V I E W
WSL · one-liner · end-to-end smoke
# install dependencies
pip install -r requirements.txt

# end-to-end smoke · HTML review in 50s
python3 scripts/e2e_smoke.py
# → /tmp/e2e_smoke_report.html (≈ 18 KB)

# or analyze frames extracted from a real mp4 recording
python scripts/analyze.py \
  --video match.mp4 --every-s 5 \
  --vlm real --llm real \
  --out report.md

If vLLM is available, it really runs the 5 decisionLLM types + full-match synthesis; if not, it falls back automatically · the pipeline still runs end to end.

R E A L - T I M E C O A C H
Windows native · four terminals · OBS prerequisite
# T1 · WSL · start vLLM (shared by perception+analysis+decision)
python -m vllm.entrypoints.openai.api_server \
  --model /path/to/Qwen3-VL-4B-FP8 --port 8000

# T2 · advice broadcast service
python -m src.advice_server --port 8765

# T3 · Windows · OBS virtual cam + tick
python -m src.live_tick --fps 2 \
  --advice-server http://localhost:8765

# T4 · Windows · PyQt overlay translucent card
python -m src.overlay_ui \
  --ws-url ws://localhost:8765/ws/advice

Prerequisites: OBS Studio · Window Capture grabbing MuMu · Start Virtual Camera. The overlay auto-finds the MuMu main window and snaps to its edge · fades in on a decision point · fades out after 8 seconds.
